# Сценарии из практики (learned)

Здесь лежат кейсы, которые **уже были прожиты**: проблема найдена, причина понята,
починка проверена на месте. Это не предполётный чек-лист и не догадка.

## Почему нельзя заранее

Регламент по наитию отвечает на вопрос «что вообще проверить в этом классе», но не на
вопрос «что это значит». В живой сессии `bd3ffb` сервер держал `Established` от станции,
а станция говорила «сервер не вижу» — такого в JSON не выложишь заранее: решают возраст
сокета, вторая сторона и момент. Поэтому порядок обратный обычному: сначала работа
(обнаружение → локализация → положительный опыт исправления), потом сценарий.

## Как создать кейс

```bash
# 1. Архив сессии уже есть: save в консоли оператора кладёт его в Data/logs/
ls Data/logs/remote-*.txt

# 2. Черновик: паспорт случая и список шагов, без причины и починки
bash scripts/scenario-from-session.sh Data/logs/remote-bd3ffb-20261119-084845.txt \
    --symptom "станция не видит МЕДОК Сервер, остальные станции работают"

# 3. Заполнить то, что знает только человек (см. ниже), затем переименовать
mv scenarios/learned/remote-bd3ffb-20261119.json.draft \
   scenarios/learned/remote-bd3ffb-20261119.json
```

Каталог меню читает только `*.json`, поэтому черновик `.json.draft` **не может**
случайно выполниться. После переименования кейс появляется в меню (раздел «Из практики»)
с меткой `[из практики]`.

## Паспорт случая (`knowledge`)

```json
"knowledge": {
  "host": "DESKTOP-3DHVKKC",
  "date": "2026-11-19",
  "symptom": "станция не видит МЕДОК Сервер",
  "root_cause": "…что было причиной, доказанно…",
  "fix": "…что помогло, одной фразой…",
  "verified": true,
  "session": "remote-bd3ffb-20261119-084845"
}
```

Это ключ для рецидива: та же машина через месяц снова «не видит сервер» — оператор
открывает кейс и видит, что уже было и чем кончилось. `verified: true` ставится **только**
после повторной проверки того же признака, а не после «вроде заработало». Сценарий с
`verified: true` без `root_cause`/`fix` не загрузится — это проверено тестом.

## Что писать в checks и fixes

- **checks** — команды, которые в этой сессии действительно дали ответ. Только чтение,
  иначе гость их отклонит (проверяется `TestScenarioCommandsAllowedOnGuest`).
- **fixes** — то, что реально помогло, с `recheck` на те же проверки: «починили и
  убедились», а не «починили и надеемся».
- **practice** — короткий текст «как это узнаётся» для следующего оператора.

Ничего не переписывайте из головы: если опыта не было — оставьте черновик черновиком.

## Секреты

Архив и lessons проходят контроль секретов при `save`, но сценарий — это файл, который
уедет на флешку. Пароли, ключи и токены в `commands` не попадают: только пути и имена
проверок.
