# FastAgent — быстрый агент с регулируемым уровнем доступа

Параллельный агент для админской флешки (классический `Agent/` не изменяется и работает рядом).
Цели: **скорость** (облачный DeepSeek первым + стриминг) и **безопасность на чужом ПК**
(уровни доступа L0–L3 + журнал действий).

## Что внутри

| Решение | Зачем |
|---|---|
| Приоритет №1 — облачный **DeepSeek** (`https://api.deepseek.com/v1`, модель `deepseek-flash`) | Первый токен ~0.9 с, не требует gpu2/Pi/WoL |
| Локальная **Ollama (gpu2 через Pi-шлюз)** вторым провайдером | Резерв, когда нет интернета/лимит; включается автоматически |
| Стриминг (SSE) с печатью по мере поступления | Ощущаемая скорость: текст виден сразу, а не через 5–30 с |
| Таймаут «первого токена» (25 с) | Мёртвый провайдер отбрасывается быстро, без ожидания полного таймаута |
| Короткий системный промпт + обрезка истории (`history_limit`) | Меньше входных токенов → меньше latency и цена |
| Уровни доступа L0–L3 с белыми списками | Агент выполняет команды, но только разрешённые на выбранном уровне |
| Журнал действий `Data/logs/actions_<дата>.log` (JSON Lines) | Видно, что и с каким вердиктом запускалось |

## Уровни доступа

| Уровень | Название | Что выполняет |
|---|---|---|
| `L0` | chat | Ничего не выполняет — только диалог и объяснения (безопасно на любом ПК) |
| `L1` | read | Только чтение из белого списка, **без подтверждения**: `ipconfig /all`, `systeminfo`, `Get-*`, `Test-*`, `netstat`, `tasklist`, `nslookup`, `reg query`, `uname`, `df`, `journalctl`, `systemctl status`… |
| `L2` | fix | L1 + безопасные починки, **каждая с подтверждением `y`**: `ipconfig /flushdns`, `netsh winsock reset`, `Restart-Service`, `sfc /scannow`, `dism … /restorehealth`, `gpupdate /force`, `systemctl restart`… |
| `L3` | admin | Любые команды, подтверждение обязательно; **опасные — двойное** (`yes`): `format`, `diskpart`, `bcdedit`, `reg delete`, `del /f`, `Remove-Item -Recurse`, `shutdown`, `Set-ExecutionPolicy`, `rm -rf`, `mkfs`… |

Ключевые правила политики (`classify()` в `main.go`):

1. Порядок проверок: **опасное → изменяющее → чтение**. Иначе `ipconfig /flushdns` поймается общим `^ipconfig` и выполнится без подтверждения (эта регрессия закрыта тестом).
2. Незнакомая команда ниже L3 — не выполняется, агент прямо говорит: «нужен уровень 3».
3. Повышение уровня в рантайме требует ввода `yes` (защита от случайного `/level 3`).
4. На L0 не выполняется ничего, даже при подтверждении.
5. **Обёртки разворачиваются**: `powershell -c "Get-Service …"`, `cmd /c …`, `sudo …` классифицируются по внутренней команде (`sudo ip addr` — чтение, `sudo rm -rf /` — опасно). `powershell -EncodedCommand …` — непрозрачная нагрузка, всегда опасно (L3 + двойное подтверждение).
6. **Токены в белых списках заякорены** (`(\s|$)`): без этого `w` совпадал с `wscript script.vbs`, `tr` — с `truncate`. Конвейер в интерпретатор (`… | bash`, `… | powershell`) и `find … -exec/-delete`, `sed -i`, `xargs`, `rm -rf /` — опасные.
7. **Подтверждение не дано = отказ** (в т.ч. при EOF stdin) — fail-closed.
8. Очистка журнала `wevtutil cl` — опасная (уничтожение следов), а `wevtutil qe/gl/el` — чтение.

## Запуск

```bat
:: с флешки (Windows)
bin\agent-fast.bat          :: уровень из Data\config.fast.json
bin\agent-fast.bat 1        :: принудительно L1 (чтение)
bin\agent-fast.bat 3        :: полный доступ (опасные — двойное подтверждение)
```

Из `START.bat` — пункт **[6]**.

Внутренние команды агента: `/level N`, `/level`, `/diag`, `/report`, `/follow on|off`, `/clear`, `exit`.

### Полевой прогон на реальном Windows (LENOVO, Windows 10 IoT LTSC 10.0.19044)

| Проверка | Результат |
|---|---|
| Стриминг облака | `ttft 0.70–1.04 с` на каждой из 13 команд |
| L1 (чтение без спроса) | `wmic os get`, `Get-Service`, `sc query`, `Get-WinEvent`, `Get-EventLog`, `Get-NetAdapter`, `ipconfig /all` — все `код 0`, реальный вывод Windows |
| Обёртки PowerShell | `powershell -NoProfile -Command "Get-Service …"` прошли политику L1 |
| L2 подтверждение | `ipconfig /flushdns` → `y` → `код 0, 0.28 с` (реальный сброс кэша) |
| L2 отказ | `resolvectl flush-caches`, `sfc /scannow` → `n` → `Отменено оператором` |
| Права | `dism /online /cleanup-image /scanhealth` → `код 1` (нужен администратор) |

Дефекты, найденные прогоном, и их устранение:

1. **Русский вывод команд был мусором** (`��������` вместо «Корпоративная LTSC»): при выводе в pipe
   нативные утилиты пишут в OEM-кодировке. Добавлено декодирование cp866/cp1251
   (`encoding.go`, настройка `windows_encoding: auto|cp866|cp1251|utf8|off`), 4 юнит-теста.
2. **Размышления модели сыпались в консоль**: DeepSeek отдаёт сотни чанков `reasoning_content`
   (по-английски) до `content`. Теперь печатается только `content`, а размышления скрыты
   (`show_reasoning: false`), в строке `[v]` — только сводка `размышлений N симв. (скрыты)`.
3. **Размышления тормозили ответ**: у DeepSeek отключаются полем `thinking: {"type":"disabled"}`
   (измерено: **ttft 0.54 с против 1.25 с**, 0 чанков reasoning вместо 208 символов).
4. **Тестовые сессии «съезжали»**: каждая строка stdin — отдельный вопрос агента, поэтому
   вопросы и ответы `y`/`n` разделены на 5 независимых сессий; L0 теперь детерминированно
   проверяет блокировку, L2-blk — блокировку опасной (`wevtutil cl`) и незнакомой команды.

### Второй полевой прогон (LENOVO, те же 5 сессий) — после исправлений

| Проверка | Результат |
|---|---|
| Шапка | `Кодировка вывода команд: cp866 (windows_encoding=auto)` |
| L0 | `[BLOCK] L0: команда не выполняется: whoami` — блокировка сработала детерминированно |
| L1 | 6 команд чтения выполнены, `[BLOCK]` — **0**; размышления в консоль не льются; U+FFFD = 0 |
| L2-no | `netsh winsock reset` → `Отменено оператором` |
| L2-yes | `ipconfig /flushdns` → `код 0, 0.30 с` |
| L2-blk | `[BLOCK] Команда запрещена на уровне L2: wevtutil cl Application`; `[BLOCK] Команды нет в белом списке: wevtutil epl …` |
| Журнал | 12 записей прогона, все вердикты и коды корректны (`approved=false` у отказов и блокировок) |

Пятый дефект, найденный во втором прогоне и устранённый: `systeminfo | findstr /C:"OS Name"`
вернул `Windows 10 IoT ????????????? LTSC` — консоль в UTF-8 (наш `chcp 65001`) заставляет
**findstr** читать OEM-байты (cp866) как UTF-8 и подменять кириллицу на `?` (модель это
заметила и написала об этом в ответе). Решение: команды разделены по типу — синтаксис
PowerShell (`Get-*`, `@{…}`, конвейеры с cmdlet'ами) идёт в `powershell`, нативные утилиты
(`systeminfo`, `ipconfig`, `wmic`, `sc`, `netsh`, `findstr`) запускаются через временный `.cmd`
с переключением `chcp <OEM> … chcp 65001` вокруг команды: кириллица снова читается, а наш
UTF-8-интерфейс не портится. Код возврата снимается до возврата кодировки.

> Примечание про `sc query type= service state= inactive` → `код 1`: это синтаксис самой команды
> (у `sc` свои капризы с пробелами после `=`), политика тут ни при чём — в журнале вердикт `чтение`,
> команда была разрешена и выполнена.

### Третий полевой прогон — кодировка вылечена, нашлись три дефекта уровня агента

Что подтвердилось: кириллица из нативных утилит читается в cp866 без подмен — `sc query` вернул
`Служба маршрутизатора AllJoyn`, `ipconfig /flushdns` — `Кэш сопоставителя DNS успешно очищен`;
U+FFFD в выводе больше нет; `[BLOCK] L0: команда не выполняется: whoami` на месте; `netsh winsock reset`
отклонён оператором; `ipconfig /flushdns` выполнен (`код 0`, 0.14 с); `wevtutil el`/`gl` (чтение)
разрешены. Стриминг: ttft 0.63–1.57 с.

Три дефекта, найденные прогоном и уже устранённые:

6. **Агент врал модели о коде возврата.** В историю диалога уходил жёстко зашитый
   `Вывод команды … (код 0)`, хотя в консоль печатался настоящий код. Отсюда и абсурд в отчёте:
   `systeminfo | findstr` завершился с `код 1` и пустым выводом, а модель написала «Отлично, код 0».
   Теперь `handleCommand` возвращает структуру `cmdResult` с реальным кодом и длительностью,
   а отказы передаются модели отдельным сообщением `Команда … НЕ выполнена: <причина>` —
   раньше модель вообще не знала, что команда не запускалась, и предлагала её повторно.
7. **`findstr` по английским подписям на русской Windows не находит ничего.** Под OEM-кодировкой
   `systeminfo` печатает локализованные подписи (`Имя ОС`, `Версия ОС`, `Тип системы`), поэтому
   `findstr /C:"OS Name"` вернул пустоту. В системный промпт добавлено правило работать с
   локалью-независимыми командами: `wmic os get Caption,Version,BuildNumber,OSArchitecture /value`,
   `Get-CimInstance Win32_OperatingSystem`, `ver`, `systeminfo` без фильтра; в `/diag`-снимок
   добавлены `wmic os` и `wmic logicaldisk`. Плюс правило «код != 0 или пустой вывод → не утверждать успех».
8. **Обрезка вывода рвала многобайтные символы.** `truncate` резал строку по байту, и на стыке
   появлялся один `U+FFFD` в журнале и в контексте модели. Теперь границы — по руне, а в пометке
   видно, сколько символов потеряно: `…[обрезано 12 симв.]`.

Дополнительно: пустой вывод теперь подсвечивается в консоли (`[i] вывод пуст при коде 1 — успех
не подтверждён.`), тест блокировок `field-L2-block.txt` требует опасную команду явно
(`wevtutil cl System`), а `field-test-fastagent.bat` предупреждает, если запущен не от администратора.

## Известные ограничения

- Стриминг: печать `AI > ` начинается до проверки провайдера, поэтому при fallback строка `[fallback]` идёт после первого `AI >` — косметика.
- `auto_followup` добавляет второй (и последующие) запрос к модели — при экономии токенов выключается `/follow off`.
- Политика работает по белым спискам (regex) — если нужной команды нет в списке, добавьте её в `reReadSafe`/`reFixAllowed` и запустите тесты.
- На Linux команды исполняются через `/bin/sh -c`, на Windows — через `powershell -NoProfile -NonInteractive -Command`.
