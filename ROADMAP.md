## ЭТАП 7: FastAgent — быстрый агент с уровнями доступа (ветка `feature/deepseek-fast-agent`)
Реализовано параллельно, классический `Agent/` не изменён.
- [x] Приоритет №1 — облачный DeepSeek по API-ключу (`deepseek-flash`); локальная Ollama
      (gpu2 через Pi-шлюз) осталась резервом и включается автоматически при 401/429/сети.
      Проверено: `[fallback] DeepSeek-Cloud-BADKEY недоступен (HTTP 401) → следующий провайдер`.
- [x] Стриминг ответа (SSE) с печатью по мере поступления; таймаут «первого токена» 25 с.
      Замер: **ttft 0.92 с** (DeepSeek), 0.13 с (локальная модель).
- [x] Регулируемый уровень доступа L0/L1/L2/L3: белые списки read-only и «безопасных починок»,
      подтверждение `y` для изменений, двойное `yes` для опасных команд, запрет вне уровня.
      Проверено физически: L0 блокирует `whoami`; L3 требует двойного подтверждения для `format C:`.
- [x] Журнал действий `Data/logs/actions_<дата>.log` (JSON Lines: уровень, вердикт, подтверждение, код).
- [x] Юнит-тесты политики доступа (`FastAgent/policy_test.go`, 35 кейсов) — нашли и закрыли
      дыру: `ipconfig /flushdns` классифицировался как «чтение» и выполнялся бы без подтверждения на L1.
- [ ] Ручные испытания на реальном гостевом Windows-ПК (SmartScreen, PowerShell, права).
- [ ] Опционально: голосовой ввод, экспорт отчёта в PDF, тайминг-профиль по провайдерам.
