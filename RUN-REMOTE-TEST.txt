ПАМЯТКА ОПЕРАТОРА: УДАЛЁННАЯ СЕССИЯ (R5)
=========================================
Клиенту уходит один файл, всё остальное — нажатия в своём терминале.
Печатать команды в сессию не нужно. Секреты и пути руками не вводятся.

ЗА 5 МИНУТ ДО ЗВОНКА (pi5) — ОДНА КОМАНДА
-----------------------------------------
  remote
(то же, что ./remote.sh из каталога admin-stick; работает из любого каталога)

Она делает всё сама: поднимает брокер на 127.0.0.1:8866 (если ещё не поднят),
берёт секрет из Data/remote-secret.txt (создаёт при первом запуске, chmod 600),
открывает меню оператора и печатает две строки:

  Сессия: <код>
  Файл-билет: ~/.cache/fastagent/fastagent-<код>.exe

Файл-билет — это и есть то, что уходит клиенту в AnyDesk. Больше ничего
передавать не нужно. Повторный запуск переиспользует уже поднятый брокер.

ГДЕ ЛЕЖИТ ФАЙЛ-БИЛЕТ
--------------------
`~` — это домашний каталог оператора (на pi5: /home/dry), а `.cache` — скрытый
каталог (в файловом менеджере виден по Ctrl+H). Полный путь:

  /home/dry/.cache/fastagent/fastagent-<код>.exe

Имя файла = код сессии из строки «Сессия: <код>». Файл создаётся в момент
создания сессии; в каталоге накапливаются билеты прошлых сессий, поэтому
отправляйте тот, что назван в вашей строке «Файл-билет».

Путь, без ошибок и без набора руками:
  remote ticket              показать полный путь к свежему билету
  remote ticket /media/dry/HBCD_PE_X64    скопировать его на флешку
  remote clean               оставить 3 свежих билета, старые удалить
  remote clean 10            оставить 10

ЕСЛИ WINDOWS ОТВЕЧАЕТ «НЕВОЗМОЖНО ЗАПУСТИТЬ ЭТО ПРИЛОЖЕНИЕ»
-----------------------------------------------------------
Значит билет — не Windows-программа (в каталоге остался билет старых версий,
когда туда попадал linux-бинарь оператора). Проверить и получить годный:

  remote status   в строке «последний файл-билет» — «Windows PE» или [!]
  remote clean    удалить старые билеты (оставит 3 свежих)
  remote          создать сессию заново и отправлять НОВЫЙ файл

Служебные команды (по необходимости):
  remote status   что запущено, где секрет, последний файл-билет
  remote stop     остановить брокер после звонка
  remote log      хвост журнала брокера
  remote help     краткая справка

КЛИЕНТУ (одна фраза)
--------------------
«Сохраните файл и запустите двойным щелчком. Появится окно «Диагностика
компьютера» — его не закрывайте, в конце оно само попрощается.»
SmartScreen: «Подробнее → Выполнить в любом случае».

ДАЛЬШЕ — МЕНЮ ОПЕРАТОРА
-----------------------
После подключения сразу выполняется стартовый блок (его не пропустить):

  [OK] эталон файла: fastagent-<код>.exe, 6.4 МиБ, sha256 … — совпадает
  [OK] секреты в файле клиента: не найдено (проверено ключей: 1)
  [OK] журнал гостя: LENOVO: C:\...\actions_remote_<дата>.log, 40 строк, 4.2 КиБ — чисто
  [--] контроль архива и уроков: при отчёте (пункт 4)

 1  Старт: эталон файла, секреты, журнал гостя
 2  Диагностика: Стандартная диагностика Windows (13 проверок)
 3  Починки (6)
 4  Отчёт: архив, уроки, контроль секретов
 5  Выход
 6  Сценарий: раздел и кейс (сейчас: Стандарт / Стандартная диагностика Windows)

Пункт 6 появляется, когда рядом больше одного сценария: там разделы (Стандарт,
МЕДОК) и кейсы. Тот же выбор можно задать заранее:
  ./FastAgent/fastagent -remote new ... -scenario medoc/imap-ukrnet
(кейсы лежат в scenarios/<раздел>/<кейс>.json; список — в пункте 6).

Нажатие 2 — все проверки подряд, на экране итог, а не простыня:
  [1/13] Критические ошибки в журнале System … [OK] критических ошибок нет
  [2/13] Критические ошибки в журнале Application … [!] критических ошибок: 7
  ...
  ── ИТОГ: проверок 13, проблем 2 ──
    [важно] Application: критических ошибок: 7
    [средне] Службы с автозапуском: 2

  ── ЧТО ДЕЛАТЬ ──
    • <проверка>        ← подсказка из сценария
      <что проверить и в каком порядке>
    Практика: <кейс>    ← накопленный опыт по разделу, показывается только
      <шаги>               когда относится к найденной проблеме

Нажатие 3 — починки списком; номер → показываются команды → одно «y» →
  выполняется, печатается код возврата. Если у починки заданы проверки
  (recheck), сразу после неё они прогоняются заново: «починили — убедились»,
  а не «починили и надеемся». Без прав администратора честно будет код 740:
  авто-повышения нет, это нормально и видно на экране.

Нажатие 4 — отчёт: txt-архив, уроки в память (если задан -memory-dir) и
контроль секретов. Если в тексте нашлись ключи — архив пишется, а уроки в
общую память НЕТ, об этом печатается предупреждение. После этого — вопрос
«Показать этот отчёт в окне клиента?»: по «y» тот же текст появляется в окне
КЛИЕНТА рамкой «ОТЧЁТ О РАБОТЕ» (коротко, без путей и команд), по «n» он
остаётся только у оператора.

Нажатие 5 — выход: журнал забирается, сессия закрывается, клиент видит
«Готово. Оператор завершил сессию — закройте это окно».

ЧТО ДЕЛАТЬ, ЕСЛИ СТАРТ НЕ ПРОШЁЛ
--------------------------------
Экран покажет, что именно: «эталон файла: размер 6 655 488 Б, а эталон 6 778 880 Б»
(старый exe — переслать файл-билет заново), «секреты в файле клиента: найден ключ
«DeepSeek»» (собрать exe заново: в бинарь не должен попадать ключ), «журнал гостя:
не получен» (гость не отвечает — проверить окно у клиента). Пока блок не пройден,
пункты 2–3 заблокированы; исправьте и нажмите 1.

Если сомнение в состоянии — одна команда: `remote stop`, затем `remote`
(брокер перезапустится чисто, секрет и билеты не меняются).

ЕСЛИ КЛИЕНТ НЕ МОЖЕТ ЗАПУСТИТЬ ФАЙЛ
------------------------------------
Флешка: `fastagent.exe -policycheck` (30/30), затем `START.bat` → [7] —
полевой тест и отчёты в `Data\logs\`; удалённая сессия в этом случае не поднимется,
но данные будут.

ЧТО АГЕНТ МЕНЯЕТ НА МАШИНЕ КЛИЕНТА
----------------------------------
Проверки (пункт 2 и кейсы) — только чтение: их команды не пишут файлы, не
трогают реестр и службы. Это проверяется тестом `TestScenarioCommandsAllowedOnGuest`
(каждая команда каждой проверки классифицируется «чтение» на уровне L1).
Исключение — сам сбор (гость пишет свой журнал в `Data\logs`), это его же файл.

Изменения — только пункт 3 (починки): номер → список команд → одно «y».
Разрешены: кэш DNS, winsock, renew/release, sfc /scannow, DISM restorehealth,
w32tm /resync, gpupdate, запуск/остановка служб. Запрещены без L3 (на клиенте
не включаем): запись в реестр, удаление файлов, установка, перезагрузка,
смена паролей/учёток, execution policy, очистка журналов.

Ничего не удаляется и не «оптимизируется» молча: крупные файлы и нехватку места
агент только показывает, решение остаётся за владельцем машины.

ЧТО ЗАБРАТЬ
-----------
  Data/logs/remote-<код>-<дата>.txt      — полная лента сессии и журнал гостя
  /home/dry/memory/projects/remote-<код>-<дата>.md — уроки (если задан -memory-dir)
  Data/logs/actions_remote_<дата>.log    — журнал гостя целиком

ЕСЛИ НУЖНА РУЧНАЯ КОМАНДА (редко)
---------------------------------
  ./FastAgent/fastagent -remote new ... -plain    — старая консоль:
  read/run/get/put/journal/save/quit. Меню остаётся путём по умолчанию.

Пошагово, без обёртки (те же вещи руками):
  ./FastAgent/fastagent -broker -broker-addr 127.0.0.1:8866 \
      -broker-secret "$(cat Data/remote-secret.txt)" -ticket-exe FastAgent/fastagent.exe
  ./FastAgent/fastagent -remote new -broker-url http://127.0.0.1:8866 \
      -broker-secret "$(cat Data/remote-secret.txt)" -ticket-exe FastAgent/fastagent.exe \
      -memory-dir /home/dry/memory
