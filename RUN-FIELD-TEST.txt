1) ЗАПУСК
---------
Вставить флешку в Windows-ПК. SmartScreen: «Подробнее → Выполнить в любом случае».
Правый клик по START.bat → «Запуск от имени администратора» → пункт [7].
(или так же: scripts\field-test-fastagent.bat)

Скрипт сам прогоняет 8 сессий + обе самопроверки + неинтерактивные -ask,
собирает один сводный файл и печатает его. Ничего вводить вручную не нужно:
ответы y/n лежат в файлах tests\, каждое — на своей строке.

2) ЧТО ДОЛЖНО БЫТЬ В СВОДНОМ ОТЧЁТЕ (8 сессий)
-----------------------------------------------
Шапка:  Кодировка вывода команд: cp866 (windows_encoding=auto)
        [i] Права процесса: администратор (высокий уровень целостности) ...
        (если [!] обычный пользователь — dism/sfc/chkdsk вернут код 740)

L0:       [BLOCK] L0: команда не выполняется: whoami
          и ответ модели о том, что при L0 команды запускать нельзя

L1:       команды чтения (systeminfo, Get-WinEvent, ipconfig /all) выполняются
          без вопросов; строка [v] DeepSeek-Cloud | ttft ... | уровень L1
          БЕЗ англоязычного «шёпота» модели перед ответом

L1-tools: НОВОЕ. Без единого вопроса y/n должны сработать декларативные
          инструменты (этап 10):
            [tool] read_file … (чтение)          -> OK
            [tool] file_glob_search … (чтение)   -> OK
            [tool] grep_search … (чтение)        -> OK
          В ответе модели — реальное содержимое win.ini и найденные пути.
          Если провайдер не умеет tools API, модель вернёт конверт
          ```tool {"name":"read_file",...}``` — это тоже штатный путь.

L2-no:    Запустить? (y/n): -> Отменено оператором        (netsh winsock reset)

L2-yes:   ipconfig /flushdns -> Запустить? (y/n): y -> код 0 (реальный сброс DNS)

L2-blk:   [BLOCK] Команда запрещена на уровне L2: wevtutil cl System
          [BLOCK] Команды нет в белом списке: mycustomtool --scan --deep

L2-tools: НОВОЕ. Инструмент write_file:
          1) «Создай файл C:\Users\Public\fa-fieldkit.txt» → вопрос
             «Записать файл? (y/n)» → y → «записано N байт» → OK;
          2) второй файл → n → «[BLOCK] оператор отказался»;
          3) read_file того же файла → содержимое «проверка записи»;
          4) запись в C:\Windows\fa-fieldkit.txt → БЕЗ вопроса:
             «[BLOCK] системный каталог — запись запрещена политикой».

L2-sfc:   sfc /scannow + dism /restorehealth → y → реальные коды возврата,
          итоги «Защита ресурсов Windows не обнаружила нарушений» и
          «Восстановление выполнено успешно». Таймаут для них — 45 мин,
          поэтому эта сессия идёт дольше всех (175 + 145 с в прошлом прогоне).

4) MCP — ОПЦИОНАЛЬНО (только если на гостевом ПК есть node/npx)
--------------------------------------------------------------
Это не обязательный шаг: без node/npx MCP-тест просто пропускается.
Если node есть, добавить в Data\config.fast.json блок:

  "mcp": {"servers": [{"name": "filesystem", "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\Users\\Public"]}]}

и запустить вручную: fastagent.exe -level 3
В шапке должно быть: [MCP] filesystem: инструментов N ... (только L3)
Затем: «Покажи список файлов C:\Users\Public инструментом MCP» →
вопрос «Выполнить внешний MCP-инструмент? (y/n)» → y → результат.
На L1/L2 MCP-инструменты модели вообще не показываются — это проверяется
строкой «Инструменты (L1): read_file, grep_search, file_glob_search».

5) ГЛАВНОЕ НОВОЕ В ЭТОМ ПРОГОНЕ (кроме инструментов)
----------------------------------------------------
1) sfc/dism: из PowerShell-выводов НЕ должно быть «#< CLIXML» (было 7 раз),
   полосы прогресса DISM сворачиваются в «…[пропущено N строк прогресса]…»,
   итоги sfc и dism видны.
2) L2-blk требует ЖИВОЙ блокировки: оператор настаивает на wevtutil cl System —
   агент обязан отказать сам: [BLOCK] Команда запрещена на уровне L2.
3) Пустой вывод при коде 0 — модель обязана проверить другой командой и
   сказать, совпали ли данные (просьба есть в tests\field-L1.txt).
4) Если модель оборачивает команду в powershell -Command "..." — в консоли
   строка «[i] обёртка powershell снята, выполняется: ...».
5) Коды возврата реальные: «[timeout]» и «Error: 740» быть не должно
   (если запущено от администратора).

6) БЕЗОПАСНОСТЬ
---------------
- На гостевом ПК меняется только: сброс кэша DNS (ipconfig /flushdns) и
  создаются два безобидных файла C:\Users\Public\fa-fieldkit*.txt.
  После теста их можно удалить: del C:\Users\Public\fa-fieldkit*.txt
- sfc/dism — встроенные средства Windows, они ничего не удаляют; перед
  подтверждением прочитайте вопрос агента.
- На флешке лежит Data\config.fast.json с API-ключом DeepSeek (и, возможно,
  Data\config.public.json с токеном шлюза) — это рабочие секреты.
  В git они не попадают, но после испытаний флешку держите при себе
  или удалите эти файлы.
