# Сценарии оператора: разделы, кейсы и практика

Здесь лежат регламенты удалённой сессии R5. Сценарий — это JSON, а не код:
новая проверка или новый кейс добавляются файлом, без пересборки бинаря.

## Раскладка

```
scenarios/
  manifest.json              эталон файла-билета (размер + sha256), пишет scripts/write-scenario-manifest.sh
  standard-windows.json      стандартная диагностика Windows
  standard-linux.json        стандартная диагностика Linux
  medoc/                     раздел «МЕДОК»
    imap-ukrnet.json         почта через IMAP ukr.net
    server-zillya.json       МЕДОК Сервер, порт 9996 и брандмауэр Zillya
```

Раздел — это подкаталог. `section`/`section_title` в JSON задают, как раздел
называется в меню: пункт **6 «Сценарий»** строит список по файлам и группирует
по разделу, поэтому новый кейс появляется в меню сам. Тот же выбор можно задать
при запуске оператора: `-scenario medoc/imap-ukrnet`.

## Что есть в сценарии

| Поле | Смысл |
|---|---|
| `checks[]` | проверки: `commands` (только чтение) + `rules` «проблема, если regex найден/не найден» |
| `checks[].hint` | одна-две строки «что делать», печатаются после итога для проваленной проверки |
| `fixes[]` | починки: команды + один вопрос; `recheck` — какие проверки прогнать сразу после успешной починки |
| `practice[]` | практика решения по разделу; `when` — показывать, только если провалилась одна из этих проверок |

Оценка проверки детерминированная: regex + направление, модель не участвует.

## Правила для новых кейсов

1. **Проверки — только чтение.** Гость выполняет их без подтверждения; команда
   вне белого списка будет отклонена, и проверка честно покажет «нужно
   подтверждение» вместо результата. Это ловит тест
   `TestScenarioCommandsAllowedOnGuest` — он прогоняет политику гостя по всем
   командам всех сценариев.
2. **Проверка должна быть воспроизводимой на живой машине.** Если команда
   зависит от установленного софта (openssl и т. п.) — либо `ignore_exit`, либо
   другой способ получить факт.
3. **Вердикт без модели.** Не «похоже, проблема», а факт: порт не открывается,
   служба не Running, в журнале N ошибок.
4. **Практика — это накопленный опыт, а не пересказ документации.** Пишется
   после реального разбора: симптом → что проверили → что оказалось → что
   помогло. Пока причина неизвестна, так и писать: «гипотеза, проверяется так-то».
5. **Секреты в сценарий не попадают.** Пароли, токены, адреса с ключами — нет:
   сценарий уходит на клиентскую машину.

## Почему «починка — и сразу проверка»

Оператор в AnyDesk не должен гадать, помогло ли. `recheck` привязывает починку к
проверкам: после успешного выполнения они прогоняются заново и заменяют итог в
отчёте. Полный прогон остаётся пунктом 2.

## Связанные проекты

`medoc-bridge` (Go + .NET, рефлексия по DLL M.E.Doc) — для более глубокого
понимания процессов внутри программы: документы, статусы, COM/.NET-обёртки.
Диагностика здесь остаётся на уровне ОС и сети, но при разборе конкретного
клиента мост полезен как источник фактов о МЕДОК.
